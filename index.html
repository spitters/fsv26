Course material

During this course we use the Rocq proof assistant (formerly Coq). Rocq is both a functional programming language and a system for reasoning about one's programs using formal proofs.

Installation. The easiest route is Docker and VS Code (Rocq 9.0, VsRocq, QuickChick, Equations preinstalled; the same image is used by the autograder). Alternatively, install the Rocq Platform 2025.08.3 (Rocq 9.0, the version the course material is tested with; see install) and choose an IDE; VS Code with VsRocq is recommended.

In the browser. The lectures use executable slides: every code block runs in the browser (no installation). The full books are available the same way. The Rocq panel opens on the right; the first visit downloads about 40 MB of libraries, so wait for the package list to finish before stepping. If the panel is missing, click the plug icon at the right edge or add ?jscoq=on to the URL. Use a recent desktop Chrome or Firefox. Scratchpad for live experiments. The QuickChick volume is read-only in the browser; run QuickChick in Docker.

We use part of the online textbook Software Foundations by Benjamin C. Pierce et al. (Logical Foundations v7.0, Programming Language Foundations, QuickChick). Links below go to the copies hosted here; the upstream pages are equivalent.

Homework

The course includes a track of weekly exercises, handed in through Classroom 50. Submission and approval of 10 mandatory assignments is required: five assignments from the first seven weeks and five from the second. Work in groups of two (exceptionally, three) is encouraged; one hand-in per group. The exercises are handed in each Friday before 11:00. To hand in, accept each assignment through its link in the schedule below (one repository per group; the first group member accepts and invites the others as collaborators); your hand-in is the last commit on the default branch before the deadline. Come prepared to the Q&A sessions so you can ask questions in person.

Rocq must accept the homework handed in as a .v file in its entirety. The exercise will not be graded if Rocq does not accept the file. Use Admitted to make Rocq accept incomplete proofs.

You are not allowed to use Rocq tactics in the homework that we have not yet discussed (for example tauto, eauto and lia are forbidden).

Rocq project

The course finishes with a Rocq project; lists of suggestions are here and here. You may also invent a Rocq project yourself, or do a variation or extension of one of the suggested projects. If you invent a project yourself or use a variation of the suggestions, you have to discuss it with the lecturer.

You are allowed to work in groups, and you may write the report together. You are fully responsible for the code and the report; the oral exam tests your understanding of all the material. From groups I expect a bigger effort, which means doing at least some of the "very hard" exercises.

To complete the Rocq project, you deliver:

  • Registration of your final project on Brightspace, due TBA. Discuss your choice with the lecturer before then, especially when proposing a project of your own design.
  • A set of Rocq .v files containing the solution to your project and a written report, due TBA.

The written report is 5 to 10 pages in academic style and includes:

  1. Name and student number.
  2. A short introduction with at least a description of the project you have chosen; do not copy the description from the projects file.
  3. A description of the problems you encountered during the project and how you solved them. If you had multiple solutions in mind, describe them and explain why you picked the one you used.
  4. A conclusion with at least your experience using Rocq: what you liked and what you did not like.

Do not include unnecessarily long excerpts of Rocq code; use small fragments to illustrate a point. Informal proofs are formulated as taught during the course. Do not paraphrase Rocq proofs in natural language ("now we apply tactic X so our goal becomes Y").

Grading

The grade reflects an overall assessment of:

  • the group project;
  • an individual oral examination, which also tests your understanding of all the material in the course.

Only students with approved exercises can attend the oral exam and thus pass the course.

The grade of the Rocq project is based on:

  1. Correctness: whether the Rocq definitions and lemmas correctly model the problem.
  2. Completeness: whether all lemmas are proven (no lemmas omitted, no proofs finished with admit or Admitted).
  3. Style: whether the Rocq code follows the style guidelines (bullets and Case markers, sensible variable names, use of implicit arguments).
  4. Effectiveness: whether the definitions and proofs are given in an effective way (no useless proof steps; the induction tactic not used blindly).
  5. Report: style, presentation, language and correctness of the report.

During the oral exam we test your understanding of the project, e.g. by asking you to explain proofs of the project informally, by querying you about the contents of your report, or by asking general questions about the contents of the course.
